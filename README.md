# 🐸 奶蛙大进化 · Milk Frog Evolution

一个受 2048 启发的奶蛙合成小游戏，使用原生 HTML、CSS 和 JavaScript 编写。通过移动棋盘，将同等级奶蛙合成为更高等级，目标是进化到 LV.10。

**在线体验：** [打开游戏](https://l-1565.github.io/Milk-Frog-Evolution/)

## 玩法

- 棋盘为 4 × 4，开局随机生成两只奶蛙。
- 使用方向键、WASD 或页面上的方向按钮移动。
- 每次操作会让整个棋盘上的奶蛙一起向同一方向滑动，无需选择某只奶蛙；可跨过多个空格，直到碰到边缘或其他奶蛙。
- 相同等级的奶蛙碰撞后升一级，每只奶蛙每次移动最多合并一次。
- 每次合并获得「新等级 × 100」分，例如两只 LV.1 合成 LV.2，获得 200 分。
- 有效移动后生成一只新奶蛙：90% 概率为 LV.1，10% 为 LV.2。无效移动不生成奶蛙。
- 达到 LV.10 即获胜；棋盘填满且没有可合并的相邻奶蛙时结束。
- 支持撤销最近 50 次有效移动、重新开始、返回首页，以及规则和图鉴说明。

撤销会恢复棋盘和分数，但不会恢复随机数序列；撤销后再次移动，生成的奶蛙可能不同。返回首页后点击开始游戏会开启新一局，当前版本不保存刷新前的进度。

## 手机端游玩

手机可通过浏览器打开上面的在线地址，无需安装 App。点击「开始游戏」，再点击棋盘下方的 ↑、←、↓、→ 按钮操作；每次点击移动整个棋盘。当前不支持在棋盘上滑动手势，也不支持点选单只奶蛙。

页面已配置移动端视口和自适应棋盘，建议竖屏游玩；屏幕较矮时向下滚动即可找到操作按钮。游戏中可查看详细规则，使用撤销、重新开始、返回首页及音效开关。

音效在点击开始游戏等交互后播放，手机的静音模式、媒体音量和浏览器设置可能影响声音。当前未完成真实 iOS/Android 设备验收；如遇布局或交互异常，请提供手机型号、浏览器及截图。刷新页面会丢失当前进度。

若更新后仍显示旧页面，可刷新或用无痕窗口打开；也可在网址末尾增加版本参数，例如 `?v=rules-1`，重新加载页面。

## 本地运行

无需安装项目依赖，也无需构建。需要现代浏览器，以及用于提供静态文件的 HTTP 服务。例如安装 Python 3 后，在项目根目录执行：

```sh
python -m http.server 8000
```

打开 <http://localhost:8000/>。Windows 也可以使用 `py -m http.server 8000`，或使用 VS Code 的 Live Server 打开根目录的 `index.html`。

项目使用 ES modules，请通过 HTTP 服务访问，不要直接双击 HTML 文件以 `file://` 方式打开。

## 目录与模块分工

```text
index.html          首页、棋盘与说明弹窗
style.css           首页及游戏样式
js/
  board.js          棋盘、移动合并、随机生成、可移动判断
  history.js        有容量限制的历史状态栈
  game.js           游戏状态、计分、撤销、重开与胜负判断
  main.js           页面事件、键盘输入与核心接口连接
  ui.js             根据游戏快照渲染页面
  effects.js        开始、移动、合成、撤销与胜负音效及静音控制
  testboard.html    棋盘算法的浏览器测试页
tests/
  core.test.js      核心规则与状态测试
  ui.test.js        使用模拟 DOM 的事件和渲染集成测试
CORE_API.md         核心接口说明
assets/frogs/       LV.1–LV.10 奶蛙图片，按等级编号
```

成员 A 负责 `board.js`、`history.js`、`game.js` 核心模块；成员 B 负责首页与界面呈现。`main.js` 和 `ui.js` 已补充联调实现，后续修改这些文件时需同时保留页面行为与核心接口的兼容性。

## 核心接口

从 `js/game.js` 导入以下函数：

| 接口 | 行为 |
| --- | --- |
| `initGame()` | 新建一局并返回状态 |
| `move(direction)` | 接受 `left`、`right`、`up`、`down`，移动并返回状态 |
| `undo()` | 恢复上次有效移动前的状态 |
| `restart()` | 清空历史并开始新一局 |
| `getState()` | 返回独立的状态快照 |
| `isGameOver()` | 返回是否已获胜或失败 |

状态包含 `board`、`score`、`highestLevel`、`status`、`canUndo`；其中 `status` 为 `playing`、`won` 或 `over`。棋盘使用 0 表示空位，1–10 表示奶蛙等级。界面应调用核心接口更新游戏，避免直接修改快照来改变游戏状态。详细约定见 [CORE_API.md](CORE_API.md)。

## 验证

使用 Node.js 22 运行自动测试：

```sh
npm test
```

测试覆盖四方向合并、计分、输入棋盘保护、随机生成、最高等级、可移动判断、历史容量、撤销、重开，以及页面事件与渲染衔接。UI 测试使用模拟 DOM，不能替代真实浏览器的布局和交互验收。

也可通过本地 HTTP 服务打开 `/js/testboard.html` 查看棋盘算法测试。发布前建议在桌面和手机浏览器检查开始游戏、移动、分数、撤销、重开及页面布局。

本项目通过 GitHub Pages 发布：仓库 **Settings → Pages**，选择 **Deploy from a branch**，来源为 **main / (root)**。推送后可在仓库 Actions 中查看部署结果。

提交修改前先获取并合并远程更新，运行测试并审阅差异。多人共同编辑首页和界面模块时，应逐项处理冲突，避免用旧文件整体覆盖其他成员的更新。
